# PR이 주는 영향
**PR**은 원격 리포에 반영되지 않은 브랜치를 로컬에서 새롭게 생성하고 새로운 브랜치의 커밋 내용을 원격 리포로 푸시하고 난 후 가능한 작업이다.

새로운 브랜치에 커밋된 사항들을 원격 리포의 main 브랜치에도 반영하기 위해 브랜치를 병합(Merge)하고자 할 때 요청을 보내는 것이라고 이해하면 된다.

# PR을 할 때 주의 사항
PR을 생성할 때, 생성 직후 바로 하단에 main 브랜치와의 병합을 확정 짓는 버튼이 나온다. 이 버튼을 누르면 바로 PR을 수락하여 main 브랜치의 내용에도 영향이 간다. 만약 조직 단위로 하나의 리포지터리에서 작업을 하는 상황이라면, PR을 생성한 후 곧바로 PR을 수락하지 않도록 주의해야 한다.

# PR을 생성한 후 곧바로 승인하는 실수를 하게 된다면
PR을 생성한 후 검토자가 검토하기 전 승인을 하게 되면 main 브랜치의 파일 내용이 의도치 않게 변경될 수 있다. 이러한 상황에선 PR 승인에 대한 커밋 내용을 revert 하여 해결하면 된다.

# 협업을 위한 PR 템플릿
조직 단위로 여러 명이 협업을 하는 상황이라면 빠르고 정확한 소통 및 작업 효율을 위해 커밋 내용을 작성하는 요령을 양식으로 정하는 것이 권장 된다.

# 오늘 배운 점과 생각 정리
예전부터 개발 지식을 습득해오면서 PR이 정확히 어떤 것을 의미하는지 이해한 경험이 없었다. 이번에 Git을 이용한 협업을 실습해보면서 다양한 Conflict 상황 및 여러 팀원의 PR 승인 순서가 주는 영향, 단일 파일에서 여러 명이 작업한 PR을 승인할 때 파일 내용의 영역이 제대로 구분되어 있지 않으면 어떻게 영향을 주는지에 대해 배울 수 있었다. 직접 문제를 부딪히며 해결하는 과정에서 흥미가 있었고, 하나씩 알아가면서 문제를 예방하는 방법까지 익힐 수 있어서 성취감도 느낄 수 있었던 것 같다. 부트캠프가 9시부터 시작하여 6시까지 진행된다는 점이 긴 시간이라고 예상했었는데 시간이 흐르고 있다는 생각조차 들지 않을 정도로 금방 지나갔다고 느껴졌다. 오늘 느꼈던 흥미를 계속 이어가서 성장하는 하루들을 쌓을 수 있으면 좋겠다.
