## 들어가며 (Situation)

부트캠프 학습 중 여러 기능을 동시에 개발해야 하는 상황이 생겼다. 메인 코드를 건드리지 않고 독립적으로 작업하기 위해 Git branch를 사용해야 했다.

## 문제 상황 (Task)

- main branch에 직접 커밋하면 안 된다는 것은 알지만, 실제로 어떤 workflow로 branch를 나누고 관리해야 하는지 불명확했다.
- 여러 기능 branch에서 작업할 때 충돌이 발생하면 어떻게 해야 할지 몰랐다.

## 해결 과정 (Action)

### 기본 branch 전략 학습

| 작업 | 명령어 | 설명 |
|------|--------|------|
| 새 branch 생성 | `git branch 브랜치명` | 현재 브랜치 기반으로 새 브랜치 생성 |
| branch 목록 확인 | `git branch -a` | 모든 브랜치 (로컬 + 원격) 확인 |
| branch 전환 | `git checkout 브랜치명` | 특정 브랜치로 이동 |
| 병합 | `git merge 브랜치명` | 현재 브랜치에 다른 브랜치 병합 |

### 실제 workflow 시도

```bash
# feature branch 생성 및 전환
git checkout -b feature/user-auth

# 기능 개발
echo "user authentication logic" > auth.js
git add auth.js
git commit -m "Add user authentication feature"

# main으로 돌아가서 merge
git checkout main
git merge feature/user-auth
```

처음엔 위 과정이 복잡해 보였지만, 반복하다 보니 패턴이 눈에 들어왔다. 각 branch가 독립적이어서 실수할 걱정 없이 작업할 수 있다는 게 가장 큰 장점이었다.

## 결과 (Result)

- main branch의 안정성을 유지하면서 동시에 여러 기능을 병렬로 개발할 수 있게 됨
- branch 전환이 이제는 자동으로 나오는 수준까지 숙련됨
- 협업 workflow의 기초를 이해하게 됨

## 더 학습하면 좋은 개념

- **Pull Request (PR)** — branch 병합 전 코드 리뷰를 받는 GitHub 기능. branch 전략과 함께 프로젝트 quality를 높이는 핵심 도구.
- **Rebase vs Merge** — 커밋 히스토리를 깔끔하게 유지하는 병합 방식. 큰 프로젝트에서 중요함.
- **Git Flow** — 복잡한 프로젝트를 위한 branch 관리 전략. main, develop, feature 등 여러 branch 역할을 정의.
- **Conflict Resolution** — 같은 파일을 여러 branch에서 수정할 때 충돌을 해결하는 방법.

**요약**
- Git branch는 메인 코드를 보호하면서 새 기능을 안전하게 개발하는 도구다.
- 기본 workflow는 branch 생성 → 작업 → merge의 3단계.
- branch 전략을 잘 세우면 팀 협업의 효율성이 크게 올라간다.
