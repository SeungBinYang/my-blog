# LF/CRLF 경고가 주는 영향
부트캠프에서 Git으로 협업 실습을 하던 중, `git add`로 파일을 스테이징할 때마다 아래와 같은 경고를 마주치게 되었다.

```
warning: in the working copy of 'feature-shop.txt', LF will be replaced by CRLF the next time Git touches it
```

**LF**와 **CRLF**는 운영체제마다 다르게 쓰이는 줄바꿈 문자다. Windows는 `CRLF`(`\r\n`)를, macOS·Linux는 `LF`(`\n`)를 기본으로 사용한다. 이 차이 때문에 같은 파일이라도 팀원의 운영체제나 로컬 설정에 따라 커밋할 때마다 줄바꿈 문자가 바뀌면서, 실제로는 아무 내용도 바뀌지 않았는데 diff 전체가 변경된 것처럼 표시되는 문제가 생긴다.

# 개인 설정만으로는 해결이 안 되는 이유
Git에는 이 변환을 자동으로 처리해주는 `core.autocrlf` 설정이 있다.

```bash
# Windows
git config --global core.autocrlf true

# macOS / Linux
git config --global core.autocrlf input
```

문제는 이 설정이 **로컬 개인 설정**이라는 점이다. 팀원 중 한 명이라도 설정을 빠뜨리거나 다르게 지정하면, 그 사람이 커밋할 때마다 다시 줄바꿈이 뒤섞이면서 같은 문제가 반복된다. 즉 개인 설정만으로는 팀 전체의 일관성을 보장할 수 없다.

# 팀 단위로 통일하는 방법: .gitattributes
가장 확실한 해결책은 저장소 자체에 `.gitattributes` 파일을 커밋해서, 팀원 각자의 로컬 설정과 무관하게 저장소 차원에서 규칙을 강제하는 것이다.

```gitattributes
# 텍스트 파일은 커밋 시 LF로 정규화
* text=auto

# 소스 코드는 항상 LF 고정
*.js text eol=lf
*.ts text eol=lf
*.py text eol=lf
*.html text eol=lf
*.css text eol=lf
*.md text eol=lf

# Windows 전용 스크립트는 CRLF 유지
*.bat text eol=crlf

# 바이너리는 변환하지 않음
*.png binary
*.jpg binary
```

이 파일을 저장소 루트에 두고 커밋해두면, 팀원이 언제 `git clone`을 받든 동일한 줄바꿈 규칙이 자동으로 적용된다.

# 이미 진행 중인 저장소에 뒤늦게 적용한다면
`.gitattributes`를 나중에 추가한 경우 기존에 커밋되어 있던 파일들은 자동으로 바뀌지 않는다. 아래 명령으로 기존 파일들을 규칙에 맞게 재정규화해줘야 한다.

```bash
git add --renormalize .
git commit -m "chore: 줄바꿈 문자(EOL)를 .gitattributes 규칙에 맞게 정규화"
```

이 커밋은 내용 변경이 아니라 줄바꿈 문자만 바뀌는 것이므로, 팀원들에게 "이 커밋은 EOL 정규화 커밋"이라고 미리 공지해두면 blame이나 diff를 볼 때 혼란을 줄일 수 있다.

# 팀 공유를 위한 체크리스트
1. 저장소 루트에 `.gitattributes` 커밋 (팀 공통 규칙)
2. 각자 로컬에서도 OS에 맞는 `core.autocrlf` 설정 (보조 안전장치)
3. 기존 저장소라면 `git add --renormalize .`로 한 번 정리
4. 정리 커밋은 별도로 분리해서 명확히 표시

# 오늘 배운 점과 생각 정리
그동안 `LF will be replaced by CRLF`라는 경고를 봐도 그냥 무시하고 넘어갔었는데, 이번에 원인을 직접 찾아보면서 이게 단순한 경고가 아니라 팀 협업에서 계속 반복될 수 있는 문제라는 걸 알게 되었다. 특히 `core.autocrlf`가 개인 설정이라 팀원마다 다를 수 있고, 그래서 근본적인 해결책이 될 수 없다는 점이 인상 깊었다. `.gitattributes`처럼 저장소 자체에 규칙을 박아두는 방식이 왜 필요한지 체감할 수 있었다. 사소해 보이는 경고 하나도 원인을 끝까지 따라가 보면 팀 전체의 협업 방식과 연결되어 있다는 걸 다시 한번 느꼈고, 앞으로도 경고 메시지를 그냥 넘기지 않고 궁금증을 가지고 파고드는 습관을 이어가고 싶다.
