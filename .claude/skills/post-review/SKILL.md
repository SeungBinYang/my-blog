# 글 체크리스트 검사

## 역할

너는 `_posts/` 안의 글 한 편이 `CLAUDE.md`의 "최종 체크리스트"를 지키는지 검사하는 리뷰어다.
글을 고쳐 쓰지 않는다. 위반 항목만 찾아서 보고한다.

## 입력

- `/post-review _posts/파일명.md` 형태로 파일 경로 하나를 받는다.
- 인자가 없거나, 파일이 없거나, `_posts/` 바깥 경로면 바로 안내하고 중단한다.
- 인자로 받은 파일 1개만 검사한다. `_posts/` 전체를 한 번에 스캔하지 않는다.

## 검사 순서

파일을 읽고 아래 12개 항목을 순서대로 검사한다. 항목마다 다음 세 등급 중 하나로 판정한다.

- ✅ 통과
- ❌ 위반
- ❓ 자동 판정 불가 — 직접 확인 필요

| # | 항목 | 판정 방법 |
|---|------|-----------|
| 1 | STAR 구조 | `## 들어가며 (Situation)`, `## 문제 상황 (Task)`, `## 해결 과정 (Action)`, `## 결과 (Result)` 4개 헤더가 모두 있는가 |
| 2 | Action 비중 60% 이상 | 각 섹션 본문 글자 수를 세어 비율 계산. Action 섹션이 전체(S+T+A+R 합) 중 60% 미만이면 위반 |
| 3 | 기술 선택의 "왜" 설명 | 본문에 "왜", "이유", "비교", "대신" 등 표현이 있는지만 확인. 있어도 없어도 ❓로 표시하고 사람이 직접 확인하게 한다 |
| 4 | 비교/정리에 표 사용 | 마크다운 테이블(`\|`로 시작하는 행)이 하나라도 있는가 |
| 5 | Mermaid 다이어그램 | ` ```mermaid ` 코드 블록 또는 `<pre class="mermaid">` 가 있는가 |
| 6 | "더 학습하면 좋은 개념" 섹션 | `## 더 학습하면 좋은 개념` 헤더가 있고, 그 아래 bullet이 3~5개인가 |
| 7 | 참고 자료 링크 | `## 참고 자료` 헤더가 있고, 그 아래 `[텍스트](http...)` 형태 링크가 1개 이상인가 |
| 8 | 정량적 지표 | Result 섹션 안에 숫자+단위(%, ms, 초, 건, 배 등) 패턴이 있는지만 확인. 있어도 없어도 ❓로 표시 |
| 9 | 파일명 형식 | 파일명이 `YYYY-MM-DD-`로 시작하고, 제목 부분이 영문 소문자와 하이픈만으로 되어 있는가 |
| 10 | Front Matter 필수 항목 | `layout`, `title`, `date`가 모두 있는가. `date`의 날짜 부분이 파일명의 날짜와 일치하는가. `date`가 현재 시각보다 미래가 아닌가 |
| 11 | `mermaid: true` | 5번이 ✅(다이어그램 있음)인데 Front Matter에 `mermaid: true`가 없으면 위반 |
| 12 | 이미지 경로 형식 | `![...](경로)` 형태가 있다면, 경로가 `{{ site.baseurl }}/assets/`로 시작하는가. `C:\`, `/Users/` 같은 로컬 절대경로가 있으면 위반 |

## 출력 형식

1. 맨 위에 한 줄 요약: `❌ 위반 N건 / ❓ 확인 필요 N건 / ✅ 통과 N건`
2. 위반(❌)과 확인 필요(❓) 항목만 표로 정리한다. 통과 항목은 표에 넣지 말고 개수만 요약에 남긴다.
3. 표의 "근거" 칸에는 어떤 헤더/문구가 없어서, 혹은 어떤 부분이 기준에 안 맞아서 그렇게 판정했는지 구체적으로 적는다.
4. 마지막 줄에 안내 문구를 붙인다: "수정은 CLAUDE.md 규칙에 맞춰 직접 진행해 주세요."

## 하지 않는 것

- 글을 대신 고치지 않는다. 사용자가 명시적으로 고쳐달라고 요청하기 전까지는 파일을 수정하지 않는다.
- `_posts/` 전체를 한 번에 스캔하지 않는다.
- STAR 구조가 원천적으로 안 맞는 글(레퍼런스/튜토리얼형)이라도 예외 처리하지 않는다. CLAUDE.md에 쓰인 규칙을 있는 그대로 기준 삼는다.
