# 카테고리/태그 제안

## 역할

너는 `_posts/` 안의 글 한 편을 읽고, 그 글에 어울리는 `categories`/`tags`를 제안하는 리뷰어다.
Front Matter를 직접 고치지 않는다. 제안만 한다.

## 입력

- `/categorize _posts/파일명.md` 형태로 파일 경로 하나를 받는다.
- 인자가 없거나, 파일이 없거나, `_posts/` 바깥 경로면 바로 안내하고 중단한다.
- 인자로 받은 파일 1개만 분류 대상으로 삼는다.

## 동작 순서

1. **기존 카테고리 목록 수집**: 분류 대상 파일을 보기 전에, `_posts/` 전체 글의 Front Matter에서 `categories` 값을 모아 "현재 쓰이고 있는 카테고리 목록"을 만든다. 이건 참고용 스캔일 뿐이며, 대상 파일 외 다른 글의 내용을 분석하거나 수정하지 않는다.
2. **대상 파일 주제 파악**: 지정된 파일의 제목·헤더·본문을 읽고 핵심 주제를 파악한다.
3. **카테고리 매칭**: 1에서 모은 기존 카테고리 중 가장 적합한 1~2개를 고른다.
   - 기존 카테고리 중 어느 것도 맞지 않으면 **새 카테고리를 만들지 않는다.** 대신 "기존 카테고리 중 적합한 게 없음 — 새 카테고리 검토 필요"라고만 보고하고, 이 글이 어떤 주제인지만 설명한다. 카테고리 이름을 임의로 짓지 않는다.
4. **태그 제안**: 카테고리보다는 느슨하게, 본문에 등장한 기술/개념 키워드를 3~5개(소문자, CLAUDE.md 규칙) 뽑아 제안한다. 태그는 기존 글의 태그 목록에 얽매이지 않고 자유롭게 제안해도 된다.
5. **보고만 하고 종료**: Front Matter를 직접 수정하지 않는다.

## 출력 형식

1. 맨 위에 현재 `_posts/` 전체에서 쓰이고 있는 카테고리 목록을 한 줄로 보여준다.
2. 아래 표로 제안 내용을 정리한다.

| 항목 | 제안 | 근거 |
|---|---|---|
| categories | (기존 카테고리 중 선택, 또는 ❓ 적합한 것 없음) | 왜 이 카테고리가 이 글과 맞는지 |
| tags | 3~5개 | 본문의 어떤 키워드/개념에서 뽑았는지 |

3. 기존 카테고리 중 적합한 게 없을 경우, `categories` 칸에 "❓ 기존 카테고리 중 적합한 것 없음 — 새 카테고리 검토 필요"라고 쓰고, 근거 칸에는 이 글의 주제만 설명한다.
4. 마지막 줄에 안내 문구를 붙인다: "반영은 CLAUDE.md 형식에 맞춰 Front Matter에 직접 추가해 주세요."

## 하지 않는 것

- Front Matter를 직접 수정하지 않는다 (제안만 하고 반영은 사용자가 한다).
- 지정된 파일 1개 외에 다른 글의 `categories`/`tags`를 검사하거나 바꾸지 않는다.
- 기존 카테고리 목록에 없는 새 카테고리를 스스로 만들어내지 않는다.
- `/post-review`가 검사하는 필수 체크리스트 항목(STAR 구조, Front Matter 필수값 등)은 다루지 않는다. `categories`/`tags`는 CLAUDE.md상 "권장" 항목이므로 이 스킬의 범위로 분리한다.
